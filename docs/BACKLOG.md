## P1 — 확인된 버그

### B1. Docker에서 신고(report)가 전부 버려짐
- **문제:** `server/lobby.js` `report()`가 `fs.appendFile('reports.log', …, () => {})`로 쓰기 실패를 무시한다. Dockerfile이 `COPY`를 root로 하고 `USER node`로 실행하므로 `/app`에 쓸 권한이 없다.
- **근거:** 컨테이너에서 `touch /app/reports.log` → `Permission denied` (2026-11-11 확인). 사용자에게는 "신고가 접수됐어요"가 뜨지만 아무것도 안 남는다.
- **고치는 법:** 신고 경로를 환경변수 `REPORTS_FILE`(기본 `data/reports.log`)로 빼고, Dockerfile에서 `RUN mkdir -p /app/data && chown node:node /app/data`, README 재배포 명령에 `-v ~/peng-kkaki-data:/app/data` 추가. 쓰기 실패는 `console.error`로 남긴다. `.gitignore`에 `data/` 추가.
- **완료 조건:** 컨테이너로 띄운 서버에 신고를 보내면 호스트의 볼륨 파일에 한 줄 추가된다. 테스트: 임시 경로를 `REPORTS_FILE`로 주고 `report` 메시지 후 파일 내용 확인.

### B2. 아무도 시작할 수 없는 "유령 방"이 방 목록에 영원히 남음
- **문제:** `server/lobby.js` `disconnect()`의 15초 유예 타이머는 `if (r?.game) return;`으로 게임 중이면 정리를 건너뛴다. 그 뒤 나머지 사람이 **나가기**(`leaveRoom`)로 나가면 `room.game.stop(); room.game = null;`만 하고 끊긴 멤버를 정리하지 않는다. `endGame()`은 호출되지 않으므로 끊긴 사용자(`ws === null`)가 방장인 방이 남는다.
- **근거:** 재현 순서 — A가 방 만들고 B 참가, 시작 → B 접속 끊김 → 16초 대기 → A 나가기. 결과: `rooms`에 방 남음, `roomList()`에 `host: "B", players: 1`로 노출, `users`에 B 토큰 남음 (2026-11-11 Lobby를 직접 호출해 확인). 그 방에 누가 들어가도 방장(B)이 없어서 시작 불가.
- **고치는 법:** `endGame()` 끝부분의 "게임 중에 끊긴 사람 정리" 블록을 함수(`purgeDisconnected(room)`)로 빼서 `leaveRoom()`에서 게임을 멈추고 `room.game = null`로 만든 직후에도 호출한다. 정리 후 사람이 0명이면 방 삭제, 아니면 방장을 접속 중인 사람으로 넘긴다.
- **완료 조건:** 위 재현 순서 뒤 `lobby.rooms.has(code) === false`이고 `users`에 B가 없다. `test/rules.test.js` 또는 새 `test/lobby.test.js`에 이 시나리오를 넣는다(가짜 ws 객체 `{readyState:1, send(){}, close(){}}`로 충분).

### B3. 신고로 디스크를 채울 수 있음
- **문제:** `report`는 연결당 초당 30개 메시지 제한 외에 제한이 없다. 한 연결이 초당 30건 × 약 300바이트 = 하루 700MB 이상 쓸 수 있다. B1을 고치면 실제로 써지기 시작하므로 **B1과 같은 PR에서** 처리한다.
- **고치는 법:** 사용자당 신고 간격 제한(예: 10초, `user.lastReport`), 신고 대상은 같은 방의 사용자 id만 허용, 파일이 일정 크기(예: 10MB)를 넘으면 쓰지 않고 경고 로그.
- **완료 조건:** 연속 신고 두 번째는 `error` 응답. 테스트 추가.

## P2 — 공개 서비스라면 필요

### S1. PR마다 테스트 자동 실행 (CI)
- **문제:** main에 "PR로만 변경" 규칙은 있지만 테스트를 돌리는 곳이 없어서 깨진 PR도 머지된다.
- **고치는 법:** `.github/workflows/test.yml` — `pull_request`와 `push`(main)에서 `actions/setup-node@v4`(node 22) → `npm ci` → `npm test`. 가능하면 저장소 설정에서 이 체크를 필수로.
- **완료 조건:** PR 페이지에 테스트 체크가 뜬다.

### S2. 방장 강퇴 + 개인 차단
- **문제:** 익명 서비스인데 욕설·방해에 대응할 수단이 "방장이 빠른 채팅만 허용"뿐이다. 신고는 로그에만 남는다.
- **고치는 법:** (1) `kick` 메시지 — 방장만, 대기실에서만, 대상은 방 멤버. 강퇴된 사람은 같은 방 코드로 재참가 못 하게 `room.banned` Set에 토큰 보관(방이 사라지면 같이 사라짐). (2) 클라이언트 `차단` — 사용자 목록에서 누르면 그 id의 채팅·말풍선을 숨김(`localStorage`에 저장 불필요, 세션 한정으로 충분).
- **완료 조건:** 강퇴 후 `joinRoom` 시 "입장할 수 없어요" 오류. 차단한 사람의 채팅이 화면에 안 보임. 테스트는 강퇴 쪽만.

### S3. WebSocket Origin 검사
- **문제:** `server/index.js`의 `wss`가 Origin을 보지 않는다. 다른 사이트가 방문자 브라우저로 이 서버에 접속해 방을 만들거나 채팅을 보낼 수 있다.
- **고치는 법:** 환경변수 `ALLOWED_ORIGINS`(쉼표 구분, 비어 있으면 검사 안 함 — 로컬 개발용). `WebSocketServer({ verifyClient })` 또는 `connection` 핸들러에서 `req.headers.origin` 확인 후 불일치면 `ws.close(4003)`. 운영 값: `https://t1516.p.ssafy.io`.
- **완료 조건:** e2e 테스트에서 잘못된 Origin 헤더로 접속하면 바로 닫힌다.

### S4. IP당 연결 수 제한
- **문제:** 연결마다 새 토큰이면 새 사용자가 되고 각자 봇 29마리 연습을 돌릴 수 있다. 서버 부담은 크지 않지만(30명 판 시뮬레이션 턴당 9ms) 상한이 없다.
- **고치는 법:** nginx `limit_conn`이 가장 쉽다(다른 프로젝트와 같은 nginx이므로 `/pengkkaki/` location에만). 서버에서 하려면 `req.headers['x-forwarded-for']` 첫 값 기준으로 IP당 연결 수(예: 10) 초과 시 `ws.close(4029)`. 같은 교실에서 공용 IP를 쓸 수 있으니 너무 낮게 잡지 않는다.
- **완료 조건:** 제한 초과 연결이 닫힌다. README 배포 절차에 nginx 설정 예시 추가.

### S5. 배포 후 열린 탭의 프로토콜 불일치
- **문제:** 서버 메시지 형식이 바뀌어도 이미 열린 탭은 옛 코드를 쓴다. 게임 코드는 `no-cache`라 새로고침하면 해결되지만 사용자는 모른다.
- **고치는 법:** `shared/config.js`에 `PROTOCOL` 숫자. 클라이언트가 `hello`에 보내고, 서버는 다르면 `{t:'outdated'}` 응답 → 클라이언트는 "새 버전이 있어요. 새로고침합니다" 안내 후 `location.reload()`. 메시지 형식을 바꾸는 PR에서 숫자를 올린다(CLAUDE.md에 규칙 추가).
- **완료 조건:** 옛 번호로 `hello`하면 `outdated`가 온다(테스트).

### S6. 보안 헤더
- **고치는 법:** `server/index.js` 정적 응답에 `Content-Security-Policy: default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; connect-src 'self' ws: wss:`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`. index.html의 인라인은 `importmap` 하나뿐이므로 `script-src 'self'`로 되는지 확인하고, 안 되면 importmap을 외부 파일로 빼거나 해시를 쓴다.
- **완료 조건:** 브라우저 콘솔에 CSP 위반이 없고 게임이 정상 동작.

## P3 — 게임성·완성도 (실제 사람들과 해 본 뒤 결정)

### G1. 후반 균열 도배 제한
- **문제:** 30명 중 20명이 유령이면 턴마다 균열 20개가 줄어든 판에 깔린다. 균열은 판 전체에 놓을 수 있고(`PR #9`), 겹침만 `dedupeCracks`로 제거된다.
- **안:** 턴당 균열 수를 `max(1, 생존자 수)`로 제한하고 넘치면 먼저 놓은 순으로 채택. 또는 유령에게 "이번 턴 균열 차례" 표시를 돌아가며 준다. 어느 쪽이든 유령 안내 카드 문구를 맞춘다.
- **완료 조건:** 테스트 — 유령 5명, 생존 2명일 때 공개되는 균열 ≤ 2.

### G2. 잠수 플레이어 자동 탈락
- **문제:** 끊기거나 시간 초과인 사람은 `autoConfirmDisconnected`로 세기 0 제자리. 큰 판에서는 녹을 때까지 여러 턴 버티며 장애물이 된다.
- **안:** 플레이어별 연속 자동 입력 횟수를 세고 2턴 연속이면 그 턴 정리 단계에서 탈락(`fallSeq`에 추가, 순위는 그 시점 기준). 접속이 돌아오면 횟수 초기화. 화면에는 "○○이(가) 자리를 비워 탈락했어요".
- **완료 조건:** 테스트 — `isConnected`가 false인 플레이어는 2턴 뒤 `alive === false`.

### G3. 효과음
- **문제:** 소리가 전혀 없다. 파티 게임에서 체감이 가장 큰 빈칸.
- **안:** 외부 파일 없이 `AudioContext`로 합성(충돌 '톡', 낙하 '풍덩', 눈보라 바람, 상자 획득 '띵', 발사 카운트). 첫 사용자 입력 뒤에만 재생(브라우저 자동재생 정책). 설정에 음소거 버튼, `localStorage`에 저장. 재생 시점은 `scene.js`의 `applyFrames`(충돌은 프레임 간 속도 급변으로 감지)와 `fallState` 시작, `playTurn`의 이벤트 분기.
- **완료 조건:** 음소거가 유지되고, 소리 없이도 모든 기능이 동작.

### G4. 30명일 때 이름표 겹침
- **문제:** `scene.js` `updateLabels()`가 모든 펭귄 이름을 항상 그린다. 30명이면 겹쳐서 못 읽는다.
- **안:** 카메라 거리 기준으로 멀면 이름 대신 색 점만, 가까우면 이름. 또는 내 펭귄·내 조준 대상 근처만 이름. 조준 단계에는 전부 보여야 하니 거리 기준이 안전.
- **완료 조건:** 30명 연습 모드 스크린샷에서 가까운 이름이 읽힌다.

### G5. 저사양 폰 성능 확인
- **문제:** 그림자 맵 2048, 눈보라 입자 6,000개, 실제 폰에서 확인한 적 없음.
- **안:** 실제 폰에서 30명 + 눈보라 상황을 보고, 느리면 `devicePixelRatio` 상한 1.5, 모바일에서 그림자 1024·입자 2,000으로 낮춘다. 판단 기준은 재생 중 30fps 이상.

### G6. 첫 플레이 안내
- **문제:** 세기와 거리 관계를 배울 장치가 화살표 채움뿐이라 첫 판에 자멸하기 쉽다.
- **안:** 메뉴에서 "처음이면 혼자 연습"을 눈에 띄게. 연습 첫 턴에만 "세기 100%면 30칸, 판 반지름은 28칸" 같은 한 줄 안내.

## 알아둘 것 (문제는 아님)

- 30명 판 측정(2026-11-11): `turnResult` 최대 40KB, 턴당 전체 전송 1.2MB, 시뮬레이션 9ms. 교실 규모는 EC2 한 대로 충분.
- `npm audit` 취약점 0개 (three, ws 두 개뿐).
- `process.on('uncaughtException')`이 기록만 하고 계속 실행한다. 상태가 꼬인 채 살아남을 수 있으나, 한 방의 타이머 예외로 전체가 죽는 것보다 낫다고 판단한 선택. Docker `--restart`가 있으므로 "기록 후 종료"로 바꿔도 된다.
- 서버 재시작 시 진행 중인 게임이 사라지는 것은 설계상 허용(README 명시).
