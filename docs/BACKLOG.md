### T1. e2e "유령 채팅" 테스트가 가끔 실패함
- **근거:** 2026-11-12 main(10e257e)에서 단독으로 5번 돌려 1번 실패(약 19초 뒤 `until` 타임아웃). 자동 매칭 브랜치에서도 같은 빈도.
- **추정 원인:** 테스트가 "B가 바깥으로 최대 세기로 쏘면 1턴 만에 떨어진다"고 가정한다. 같은 판의 봇과 부딪히거나, 서버를 띄울 때 `WARMING_CHANCE`·`BLIZZARD_CHANCE`를 0으로 끄지 않아 이벤트가 끼면 B가 살아남아 turn 2 조건을 영영 못 맞춘다(확인은 아직 안 함).

## 알아둘 것 (문제는 아님)

- 30명 판 측정(2026-11-11): `turnResult` 최대 40KB, 턴당 전체 전송 1.2MB, 시뮬레이션 9ms. 교실 규모는 EC2 한 대로 충분.
- `npm audit` 취약점 0개 (three, ws 두 개뿐).
- `process.on('uncaughtException')`이 기록만 하고 계속 실행한다. 한 방의 타이머 예외로 전체가 죽는 것보다 낫다고 판단한 선택. Docker `--restart`가 있으므로 "기록 후 종료"로 바꿔도 된다.
- 서버 재시작 시 진행 중인 게임이 사라지는 것은 설계상 허용(README 명시).
- IP당 연결 제한은 `X-Forwarded-For`를 믿는다(nginx 뒤 기준). nginx 없이 직접 노출하면 `TRUST_PROXY=0`으로 두어야 헤더 위조로 제한을 피할 수 없다.
- 신고는 `data/reports.log`에 쌓이기만 하고 보는 사람이 없다. 운영자가 주기적으로 열어 보거나, 필요해지면 `/admin` 같은 조회 수단을 만든다.
- 개인 차단은 게임 화면 사용자 목록의 🔇(채팅 숨김)로 한다. 대기실에는 없음(대기실은 방장 강퇴로 처리).
